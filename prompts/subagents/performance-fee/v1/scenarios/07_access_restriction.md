# 7. 고객·다른 모집인 상세정보 고정 안내

대원칙: 고객별 실제 상세정보는 조회하거나 추측하여 제공하지 않는다.
PERFORMANCE_FEE와 관련된 요청만 이 시나리오로 분류한다.
고객 이름 자체가 분류 근거는 아니다. 고객 신규 여부는 TABLET,
가처분 대상 여부는 QUALIFICATION, 자동납부 연결 상태·취소는 RP다.
parameters는 {}이며 같은 제한 요청에 조회 detail을 중복 선택하지 않는다.

## OTHER_RECRUITER_DATA_REQUEST
본인이 아닌 다른 모집인의 실적·환산·수수료·원천징수 정보 요청.

## CUSTOMER_DISPOSAL_REASON_REQUEST
폐기·회입 사유, 폐기 시기, 폐기된 고객이 누구인지 묻는 문의.
고객 이름이 없더라도 폐기 사유가 뭐야? / 회입 사유가 뭐야? /
이 사람들 언제 폐기한거야? / 누가 폐기한건지 알 수 있어? / 왜 폐기했어?를 포함한다.
이는 사유·대상 확인 요청이며 본인의 폐기 건수·점수·회입 금액 조회와 다르다.
본인의 실제 건수·금액은 DISPOSAL_FEE_SUMMARY를 유지한다.

## CUSTOMER_SALES_PERFORMANCE_REQUEST
고객 자동차·차량·삼성전자 구매의 실적 영향과 매출 확인 문의.
고객 이름이 생략된 발급 후 구매 시기 문의도 포함한다.
예: 발급하고 바로 자동차 산다는데 괜찮아요? /
고객 자동차 샀다는데 환산 빠져요? / 지난달 고객인데 차사면 수수료 뱉어내요? /
고객이 삼성 전자제품 사면 점수 빠져요? /
카드 발급하고 삼성전자 실적 안빠지는거 언제부터 돼요?
고객 구매에 대한 이 안내는 일반 산정 기준 분류보다 우선한다.
모집인 본인의 전체 미반영 건수·내역 조회는 COMPOSITE_CONVERSION_EXCLUDED다.

## CUSTOMER_WITHDRAWAL_REQUEST
고객 카드 탈회 여부·이력·사유 확인.
예: 지난달 고객 탈회한 것 같은데 봐주세요 / 고객 탈회 사유가 뭐예요?
폐기·회입 사유와 분리한다. 전체 탈회 관련 환산 미반영 집계와도 구분한다.

## CUSTOMER_CONVERSION_REQUEST
특정 고객의 점수·환산이 반영됐는지 확인하는 문의.
관리비·도시가스·통신·전화요금·전기·4대보험·사회보험·건강보험·연금·
고용보험·산재보험 등 서비스 종류와 무관하게 고객별 반영 여부이면 선택한다.
예: 고객 관리비 점수 올라왔어? / 고객 통신 환산 반영 됐어?
자동납부 연결 자체의 상태·매출은 RP, 고객 환산점수 반영은 이 detail이다.
모집인 본인의 항목별 합계는 기존 복합환산 조회를 유지한다.

## CUSTOMER_UNREGISTERED_IDENTITY_REQUEST
미등록·타인수령·업체인계·미수령 고객이 누구인지, 고객명을 요구하는 문의.
예: 그럼 타인수령건 누구인지 알 수 있나요? / 누가 안받은건지 알려주세요 /
(미등록 조회 문맥에서) 고객명 좀 알려주세요.
문맥 없는 고객명을 임의로 미등록 고객이라고 가정하지 않는다.
미등록 유형별 전체 건수 조회는 UNREGISTERED_MEMBER_SUMMARY다.

## CUSTOMER_PERFORMANCE_DETAIL_REQUEST
위 전용 detail에 해당하지 않는 실적·수수료 관련 고객별 상세정보의 안전한 고정 안내.
전용 detail이 일치하면 그것을 우선한다. 다른 업무의 고객 질문을 흡수하지 않는다.
