# 4. 고객 RP 고정 안내

대원칙: 고객별 실제 상세정보·접수·매출·연결 상태는 조회하거나 추측하지 않는다.
아래 세 detail은 RP_FIXED_GUIDANCE 소속이며 MCP·문서 조회 없이 고정답변을 반환한다.
아파트·관리비·도시가스·전기·통신·전화·휴대폰요금·4대보험·사회보험·
건강보험·국민연금·연금보험·고용보험·산재보험에 공통 적용한다.
서비스마다 detail을 복제하지 않고 요청 목적을 의미로 분류한다.

## RP_APPLICATION_CANCEL_GUIDANCE
고객의 RP 신청건·접수건·연결을 취소하거나 삭제해 달라는 요청,
그 고객 신청건의 취소 가능 여부 확인.
예: 고객 관리비 연결한거 취소 가능해? / 고객 도시가스 접수 취소 /
회원 사회보험 연결 취소 / 고객 전기 삭제해줘 / 통신요금 RP 취소.
일반적인 해지 방법·처리 절차를 설명해 달라는 문서 질문과 구분한다.

## RP_CUSTOMER_PAYMENT_GUIDANCE
특정 고객의 실제 연결 금융기관·카드사·은행·자동납부·매출·접수 상태,
고객 개인의 연결 가능 여부 확인.
예: 고객 관리비 어느 카드사로 연결됐어? / 우리 카드로 연결중이야? /
고객 지난달 아파트 연결했는데 매출 떴어? / 가스요금 어디로 나가? /
고객 건강보험 은행 어디야? / 연금 내고 있어? /
회원 4대보험 연결 가능해? / 고객 휴대폰 접수 봐줘.
고객별 환산점수 반영은 PERFORMANCE_FEE 업무이며 연결 상태로 바꾸지 않는다.
실제 아파트 단지의 지원 여부 검색은 APARTMENT_RP_LIST로 유지한다.

## RP_POST_ISSUANCE_APPLICATION_GUIDANCE
카드 발급 후 RP 사후 신청·연결 가능 여부 또는 방법 문의.
고객 이름이 없어도 "카드 발급한 뒤에 RP 신청할 수 있어?"이면 선택한다.
고객 대신 자동납부 접수·신청을 실행해 달라는 요청도 포함한다.
예: 접수할 때 관리비 연결 못했는데 지금 할 수 있어? /
고객 어제 발급했는데 연금 신청 어떻게 해? / 고객 전기요금 접수해줘 /
카드 발급하고 통신·가스·관리비·보험·전기 연결 가능해?
발급 이후 조건이 없는 일반 "도시가스 자동납부 신청절차 알려줘"는 문서 GUIDE다.

## 출력 및 우선순위
동일한 요청을 고정 안내와 RAG·집계 조회에 중복 매핑하지 않는다.
취소 요청은 취소 안내, 사후 신청 또는 신청 실행은 사후 안내,
나머지 고객 연결 상태 확인은 고객 자동납부 안내를 선택한다.
서로 독립적인 복수 요청은 각각 해당 detail을 선택할 수 있다.
flat schema에서는 사용하지 않는 모든 parameter 값을 null로 반환한다.
선택 후 애플리케이션의 match.parameters는 빈 객체 {}로 정리된다.
